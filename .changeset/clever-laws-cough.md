Read the design tokens from global CSS. The new `globalCss` option lists the global stylesheets that declare them, in cascade order: paths relative to the config, or package specifiers resolved through `exports` with the `style` condition; `@import` is followed. A token is a custom property declared at `:root` (also inside `@layer`) or registered with `@property`, and its prefix names its category (`--color-*`, `--spacing`, `--radius-*`…); a category is restricted once the global CSS declares a token of it. A token name the global CSS does not declare is reported as `tokens/<category>` together with the closest declared name, so a typo such as `var(--color-fg-bsae)` no longer passes. A name without a category prefix is internal to the global CSS: a module that uses or declares it is reported as `tokens/internal`. A mode (`.dark`, a `:root` inside `@media`…) may only override a token; a new name there is reported as `tokens/undeclared`. The project's own global CSS is checked too, and global CSS must be standard CSS: an at-rule such as Tailwind's `@theme`, an import that cannot be resolved or a stylesheet that is also a CSS module stops `check` with an error. `loadGlobalCss` returns each token with its category and its value with aliases resolved; `checkCss(analysis, globalCss)` and `checkGlobalCss(globalCss)` are the pure checks.
